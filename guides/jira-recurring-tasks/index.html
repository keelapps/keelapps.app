How to create recurring tasks in Jira Cloud

Jira Cloud · Updated 12 October 2026

A weekly report, a monthly maintenance check, a quarterly access review, a yearly licence renewal: work that comes back on a calendar. Jira Cloud can repeat a work item on its own up to once a month. For quarterly, yearly or “first Monday” you build an Automation rule. This guide shows both, gives cron expressions you can copy, and explains how to keep a recurring task from piling up when nobody closes the last one.

We make Recur, one of the options below, so we are not neutral. The two built-in routes come first and need no app.

Option 1: Set to recur

Jira Cloud has a built-in way to repeat a single work item. Open the work item, open the Automation menu (the lightning bolt) and choose Set to recur. You then pick:

  • How often: daily, every weekday, weekly, every two weeks or monthly.
  • When the next one appears: on the schedule, or only after the current one is completed.
  • When the series ends, if it ever should.

Behind the scenes this creates a managed Automation rule that clones the work item. It is the quickest answer for a weekly or monthly task. Its limits:

  • Nothing longer than a month. No quarterly, every six weeks or yearly. The request, JRACLOUD-94173, is still gathering interest.
  • No “first Monday” or “last Friday”. Monthly means a date.
  • No time zone choice. It runs at the time of day you set it up.
  • It uses your automation allowance. Atlassian counts the managed rule’s executions toward your plan’s usage.

Option 2: an Automation rule

For any schedule Set to recur cannot express, build the rule yourself. A quarterly access review looks like this:

  1. Project settings → Automation → Create rule.
  2. Trigger: Scheduled. Switch to a cron expression and enter 0 0 9 1 1,4,7,10 ? *, which is 09:00 on the first day of each quarter. Check the time zone the rule runs in.
  3. Turn off the option to run only on work items found by JQL. You want the rule to run with no search at all.
  4. Action: Create work item. Set the project, work type, summary, assignee and due date. Smart values help here: Quarterly access review {{now.format("yyyy-MM")}} gives each one its own name.
  5. Turn the rule on. Use Run rule once to check the result.

This is free and flexible. The costs show up later:

  • One rule per task. Ten recurring tasks is ten rules to keep in step, each with its own cron line.
  • Usage. Every run counts toward your plan’s automation allowance, the same as Set to recur.
  • No calendar preview. You find out the next date by reading the cron expression, or by waiting.
  • “Why was there no work item on Monday?” The answer is in the rule’s audit log, which project members usually cannot see.

Cron expressions to copy

Automation’s Scheduled trigger uses the seven-field Quartz format: seconds, minutes, hours, day of month, month, day of week, year.

ScheduleCron expression
Every Monday at 09:000 0 9 ? * MON *
First day of every month at 09:000 0 9 1 * ? *
First Monday of every month0 0 9 ? * MON#1 *
Last Friday of every month0 0 9 ? * 6L *
Last day of every month0 0 9 L * ? *
First day of each quarter0 0 9 1 1,4,7,10 ? *
First Monday of each quarter0 0 9 ? 1,4,7,10 MON#1 *
Twice a year, 1 January and 1 July0 0 9 1 1,7 ? *
Once a year, 15 March0 0 9 15 3 ? *

Cron counts calendar months, not intervals from a start date. “Every six weeks” has no cron expression; you need a different approach for that.

Keeping them from piling up

The usual way a recurring task goes wrong: nobody closed last month’s, this month’s arrives anyway, and after a quarter there are three of the same thing in the backlog. Decide up front which of these you want:

  • Create it anyway. Right for reports: not having written last week’s is no reason to skip this week’s.
  • Skip this round. Right for checks: one open “Check backups” is enough. In an Automation rule, add a Lookup work items action with JQL such as summary ~ "Check backups" AND statusCategory != Done, then an If condition that {{lookupIssues.size}} equals 0 before the Create action.
  • Wait for it to close. Set to recur’s “after completed” mode does this, but it then drifts: the next date counts from when the last one was closed, not from the calendar.

Option 3: a recurring-task app

Several Marketplace apps create work items from templates on a schedule. When comparing them, check:

  • The schedules you actually need: every N months, the nth weekday, a fixed hour in a time zone that survives daylight saving.
  • What happens when the last one is still open, per task, not one setting for the whole site.
  • A history that explains silence. A recurring task that quietly creates nothing is worse than none; the app should say why it skipped.
  • Where your data goes. An app on Forge with no external servers keeps issue data inside Atlassian; one with its own backend needs its own review.
  • Whether it uses your automation allowance.

For one weekly or monthly task, Set to recur is the simple answer. For a few quarterly ones, an Automation rule each is fine. Once a team has many recurring tasks, or the automation allowance is tight, templates in one place are easier to keep in step.

Questions

Can Jira Cloud create recurring tasks without an app?

Yes. Set to recur on a work item repeats it daily, every weekday, weekly, every two weeks or monthly. For anything else, such as quarterly or the first Monday of the month, build an Automation rule with a Scheduled trigger and a Create work item action.

How do I create a quarterly recurring task in Jira?

Set to recur does not offer quarterly; the request is JRACLOUD-94173. Create an Automation rule with a Scheduled trigger, use a cron expression such as 0 0 9 1 1,4,7,10 ? * (09:00 on the first day of January, April, July and October), and add a Create work item action.

Do recurring tasks count against my Jira automation limit?

Yes, both ways. Set to recur is a managed Automation rule, and Atlassian counts its executions toward your plan’s usage, the same as a rule you build yourself.

How do I stop recurring Jira tasks from piling up?

Either create the next one only when the last is done (Set to recur’s after-completed mode), or add a condition to your Automation rule that looks up open items from the same series with JQL and stops when it finds one.

Where Recur fits

Recur for Jira is option 3. Each project gets a Recurring Tasks page where you keep templates: work type, summary, description, assignee (fixed, or rotating through a list), priority, labels and a due date. Summaries take {{date}} and {{n}}, so TLS renewal check #4 numbers itself.

Schedules are every N days, every N weeks on chosen weekdays, every N months on a date, or every N months on the nth weekday, at an hour in a time zone you pick. The editor shows the next ten dates before you save. Each template chooses what happens when the last one is still open: create anyway, skip, or wait for it to close. Its run history names the result of every run, including the ones that created nothing.

Recur runs on Atlassian Forge with no external servers, and it uses none of your automation allowance. What it does not do: sub-tasks, rich-text descriptions, or cloning an existing work item with all its fields. It is free for sites of up to 10 users.
