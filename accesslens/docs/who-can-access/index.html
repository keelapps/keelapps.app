keelapps/AccessLens/Documentation

See which projects a group or user can access

Jira Cloud shows permissions one project at a time. The Explore tab turns that around and answers from the whole site, against a snapshot you choose.

Three directions

  • By group: every project the group can reach, and with what.
  • By user: everything the user can reach, including access inherited through group membership. Listed apart: what every licensed user can reach. A snapshot does not record who holds Jira access, so those rows say they apply if the person does.
  • By project: everyone who can reach it, flattened.

Effective access, not the scheme as written

Access held through project roles and group membership is expanded for you, so what you see is effective access rather than what the scheme literally says. Each result carries a provenance line naming the snapshot and when it was taken.

Who is in a group, and where else it is used

Under By group, click Check members and other uses. AccessLens reads Jira at that moment and lists the group's members, the products it gives access to, the notification schemes that email it, the filters that are shared with it, editable by it, emailed to it or name it in JQL, and the dashboards shared with it. Run it before you delete or rename a group.

Some places can't be checked: global permissions, issue security levels, workflows, group picker fields, board and plan settings, Jira Service Management settings and other apps. They are listed under every result, so an empty list never reads as "not used". The result exports to CSV.

Groups and members for project admins

Jira lets a project admin add a group to a role but only shows site administrators who is in it. Under Settings → Project settings page, a site administrator can turn on Groups and members. Each project's admins then find it under Project settings → Apps. It lists the groups the project uses, what each can do there, and who is in them. It starts off, and AccessLens checks with Jira that the person asking administers that project before it shows anything.

Checking by hand

To do the same thing with Jira's own screens or the REST API, and for what else a group can be wired into, see the guides Which Jira projects can a group access? and Which Jira projects can a user access?

Every lookup exports to CSV: see Export to CSV.
