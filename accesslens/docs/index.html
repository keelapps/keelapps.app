Get started with AccessLens

AccessLens answers “who can access what” for a whole Jira Cloud site. It reads every project's permission scheme, roles and group members once, keeps that as a dated snapshot, and answers from it. It only reads: it never changes a permission.

Where to find it

After installing, open Jira → Settings → Apps → AccessLens. The app is one admin page with four tabs: Explore, Snapshots, Reviews and Settings. Jira shows that page to site administrators only.

A site administrator can also turn on a Groups and members page in each project's settings, under Settings → Project settings page. It shows that project's admins the groups the project uses and who is in them. It starts off.

Three steps

  1. Take a snapshot. Snapshots → Take snapshot now. See Take a permission snapshot.
  2. Ask who can access what. Explore → By group, By user or By project. See See which projects a group or user can access.
  3. Keep the evidence. Compare two snapshots, or run an access review and export the signed record.

The first time you open the app, Explore shows the same three steps.

Every page

  1. Take a permission snapshot

    How an AccessLens snapshot reads every Jira project's permission scheme and roles, how large sites are scanned, and why only one scan runs at a time.

  2. See which projects a group or user can access

    Use AccessLens Explore to list every Jira project a group or user can reach, or everyone who can reach one project, with roles and group membership expanded.

  3. Find projects open to anonymous users

    AccessLens flags Jira projects that anonymous users can browse, permissions granted to every licensed user, and permissions granted to service desk portal customers.

  4. Compare permissions between two dates

    Compare two AccessLens snapshots to see every Jira permission granted or revoked between them, one row per real change rather than a stream of events.

  5. Run a Jira access review and sign it off

    Run a project-by-project Jira access review in AccessLens: confirm or flag each project, sign off when nothing is pending, and export a record auditors can use.

  6. Schedule scans and keep snapshots

    Set AccessLens for Jira to take a permission snapshot every week or month, and choose how many snapshots to keep. Old snapshots are never deleted automatically.

  7. When AccessLens cannot see everything

    What AccessLens does when a Jira site does not allow reading group members, or a project's permission scheme cannot be read: it says so instead of under-reporting.

  8. Export permissions to CSV

    Every AccessLens view exports to CSV: lookups, snapshots, diffs and sign-off records, built in your browser with a header naming the snapshot and scan window.

  9. Permissions AccessLens requests

    The four scopes AccessLens for Jira requests and what each is for. The app makes no write requests and has no external permission, so data stays in Atlassian.

  10. AccessLens questions

    Short answers about AccessLens for Jira: whether it changes permissions, who can use it, past dates, archived projects, licences, data and price.
