For Jira Cloud teams with work on a calendar

The work that has to happen every month, happening every month.

Weekly reports, monthly patching, quarterly access reviews, certificate renewals. Recur creates the issue on schedule, in the time zone you picked, and tells you exactly what it did — including the times it deliberately did nothing.

Coming to the Atlassian Marketplace Runs on Atlassian. Nothing leaves your tenant.

Recurring issues have been requested in Jira Cloud since 2011 (JRACLOUD-5185) and Atlassian closed the request as Won't Do. Automation for Jira is the usual suggestion, but it reacts to events — when this happens, do that. A calendar is not an event, and "create it unless last month's is still open" is not a rule it expresses.

What it does

Never pile up the same task twice

Decide per template what happens when the last issue is still open: create anyway, skip this round, or hold it and create it the moment the previous one closes. Every skip is recorded with its reason.

See the next ten runs before you save

The editor previews ten occurrences as you type, in the template's own time zone. Nothing surprises you after you save.

09:00 stays 09:00

Each template picks an IANA time zone. Occurrences are built as local calendar dates and converted last, so a daylight saving change moves the UTC instant and not your morning.

Month ends that behave

Monthly on the 31st runs on 28 February, or the 29th in a leap year. First Monday, last Friday and every-N-months are all first-class.

An account of every run

Created, skipped, waiting or failed — with the issue key, or the reason there is none. Failed runs retry in one click, and a failure never stops the series.

Rotate the duty

The assignee can walk a list and wrap around, so the same person is not on the hook every week. Deactivated accounts are skipped with a warning rather than silently assigned.

The Monday morning report, end to end

  1. Start from a sample

    Weekly report, monthly maintenance or quarterly review — project, issue type and time zone already filled in.

  2. Write the issue once

    Summary and description take {{date}} and {{n}}, so each issue names its own week and counts itself.

  3. Check the ten-run preview

    Against a real calendar, in the template's zone, before anything is saved.

  4. Read the history when someone asks

    Every Monday accounted for: the issue it created, or why it did not.
