keelapps/Satchel/Documentation

Scan a project's attachments

An inventory records, for every attachment in the project: filename, byte size, media type, upload date, uploader, and the issue and issue type it belongs to. It stores metadata only, never file content.

The duplicate and storage reports are computed from it.

How many are kept

The ten most recent inventories per project are kept; creating an eleventh deletes the oldest. Whoever ran one, or a project or Jira administrator, can delete it from the project page. A new inventory can start once the last has finished, at most every ten minutes.

Who sees which rows

The inventory runs as the app rather than as you, because a queued background job has no signed-in user, so it can reach issues some project members cannot see. Every time its rows are read (the list, the reports and the numbers), they are filtered to the issues the person reading can see in Jira. If Jira cannot be asked in time, nothing is shown. Anything you then download is fetched as you.

CSV export

The whole inventory exports as CSV: one row per attachment with its metadata. Useful when the person who has to approve a deletion is not the person running the app.
